# Развёртывание на Timeweb Cloud App Platform

## Настройки деплоя

Проект запускается как Node.js приложение через Dockerfile в корне репозитория.

- Способ деплоя: **Dockerfile**
- Путь до проекта: `/` (корень репозитория)
- Порт контейнера: `3000` (Dockerfile объявляет `EXPOSE 3000`)
- Команда запуска вручную не нужна: контейнер запускает `npm start`
- Не указывайте `npm start` в команде сборки. Сборка устанавливает зависимости, запуск контейнера стартует сервер.

Сервер слушает `0.0.0.0` и использует `PORT`, если его задаёт платформа. Для проверки доступности используйте `/healthz` — сервер вернёт `{"status":"ok"}`.

## Переменные окружения

Добавьте значения в настройках приложения Timeweb, не в репозиторий:

| Переменная | Для чего нужна |
| --- | --- |
| `UPSTASH_REDIS_REST_URL` | HTTPS URL базы Upstash Redis |
| `UPSTASH_REDIS_REST_TOKEN` | Токен Upstash с правом чтения и записи |
| `ADMIN_PASSWORD` | Пароль входа в панель администратора |
| `MAX_BOT_TOKEN` | Токен MAX бота |
| `MAX_WEBHOOK_SECRET` | Секрет проверки webhook; должен совпадать с настройкой webhook в MAX |
| `BOT_USERNAME` | Имя бота, используемое для создания ссылок |

Для совместимости с ранее созданными переменными Redis сервер также понимает `KV_REST_API_URL` и `KV_REST_API_TOKEN`. Основные имена для нового деплоя — `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`.

## После деплоя

1. Дождитесь завершения сборки и статуса работающего контейнера.
2. Откройте `/healthz`; ответ `{"status":"ok"}` подтверждает, что Node.js сервер запущен.
3. Откройте `/` и `/admin.html`.
4. В MAX укажите webhook URL `https://<домен-приложения>/api/webhook`.
5. Проверьте создание и загрузку заказов в админ-панели. Для работы API должны быть настроены Redis и `ADMIN_PASSWORD`.

Исходный код можно обновлять обычным коммитом и отправкой в подключённый репозиторий. После этого запустите новый деплой в App Platform.
